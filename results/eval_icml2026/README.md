# ICML 2026 reference set

Reference recipes transcribed from ICML 2026 papers. Each one pairs a claim the authors
actually make with the experiment chain they actually ran, so the standard is a
peer-reviewed experimental design rather than another language model's output.

Run anything in this directory with both env vars set:

```sh
NORM_CARDS_EVAL_ROOT=results/eval_icml2026 \
NORM_CARDS_CLAIMS=norm_cards/data/icml2026-claims-v1.jsonl \
  python -m norm_cards.eval.reference --check
```

Without them the harness reads the DARPA sprint set in `results/eval_v2/` instead.

## Contamination

The point of drawing on ICML 2026 is that a proposer's parametric knowledge of these
experiments should be weak. That property comes from the **arXiv v1 date**, not from the
venue: sampling 24 random ICML 2026 papers found roughly two thirds already on arXiv by
Jan–Mar 2026, at submission time. All three papers here first appeared after 2026-05-29,
and `norm_cards/scify_proposer.py` has no web access, so pretraining is the only channel.

Check any candidate before adding it. Papers never posted to arXiv are the cleanest, but
their PDFs are only on OpenReview, which serves a challenge page to scripted clients.

## Status

**Not yet reviewed by a human.** Every `provenance.author` says so. The steps, numbers
and thresholds are transcribed from the sources, but three things need sign-off before
these are used to produce a reportable number:

1. **The claim statement.** Each is a rewriting of the paper's own claim into a single
   falsifiable sentence.
2. **The role mapping.** Papers do not label their experiments gate/apparatus/headline/
   control. That assignment and the refute-first ordering are the annotator's, and it is
   recorded in `provenance.notes` for each reference.
3. **Scope.** What counts as part of the recipe versus an appendix detail left out.

Every step here is `origin: "paper"` — nothing was invented to fill an empty role. See
`docs/reference_format.md` for why that field exists and what it is for.

## Proposals and judgments

`proposals/` holds one file per claim with an arm per proposer model, generated by:

```sh
NORM_CARDS_CLAIMS=norm_cards/data/icml2026-claims-v1.jsonl \
  python -m norm_cards.eval.propose \
    --models gpt-5.4,gpt-5.5,gpt-5.6 --out results/eval_icml2026/proposals
```

Every arm is the **no-norm-card** condition, so the only thing varying is the model.
The claim is decomposed once per problem by a fixed decomposer (`gpt-5.5` by default)
and the resulting subclaims go to every arm — decomposition is a separate pipeline
stage, and letting each model decompose its own claim would fold two capabilities into
one number and leave the arms working from different problems.

Scoring those arms:

```sh
NORM_CARDS_EVAL_ROOT=results/eval_icml2026 \
NORM_CARDS_CLAIMS=norm_cards/data/icml2026-claims-v1.jsonl \
  python -m norm_cards.eval.evaluate \
    --problems all --source results/eval_icml2026/proposals --judge-runs 3
```

The judge is blind to which model produced a set.
